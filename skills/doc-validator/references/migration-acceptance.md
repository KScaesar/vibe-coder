# Migration 驗收細則

適用條件：Migration 模式（有來源文件，把內容重組或拆分為多份文件）時才讀。主檔 `SKILL.md` 的 Validation Process 只給步驟，本文件補判斷標準與結果記錄格式。除硬規則外，數字與門檻都是提示，依情境裁量。

## 1. 正向對照：來源 → 新文件

先讀來源，再讀新文件（有實作者回報時的閱讀順序見 [review-protocol.md](review-protocol.md) 第 1 節）。依來源順序逐章節、逐段落回答：「這段的內容，能在新文件的某處找到嗎？」

- 不要求文字一致。被改寫、合併、拆開、移到不同類型的檔案，只要意思相同就算找到。
- 找到：記下位置，繼續。
- 找不到：先歸類，不要立刻判不合格。

### 省略清單的分類

| 類別 | 定義 | 判定 |
|---|---|---|
| 過細 | 對「目標讀者」沒有影響，例如逐行範例、重複前文的內容、與單一工具綁定的逐項注意事項。判準要指明是對哪一種讀者：只對特定語言或工具的使用者有影響，但對其他讀者沒有，要分開處理，不能一概視為過細 | 可省略 |
| 過程紀錄 | 純時間序敘述、補洞用的過程用語。其中說明「為何選這個、不選那個」的理由與代價屬於決策內容，要留，可改寫成不帶版本的說法；已改寫保留理由的，記為「過程紀錄（已改寫保留）」 | 可省略 |
| 明列刪除 | 使用者或交接文件事先明確列出可刪的內容（如整節索引）。仍須列入清單並引用授權出處 | 可省略 |
| 其他 | 規則、行為、定義、案例、決策與其理由、使用者必須遵守的要求 | 必須補回；未補回即不合格（硬規則）。補回後標「已補回」並記新位置 |

- 前三類必須出現在省略清單並說明歸類原因；審查者不同意歸類時視為「其他」。
- 清單固定欄位：來源章節、內容摘要、類別、理由、新位置（已改寫保留或已補回者才有）。

### 「找得到」的判斷標準

| 內容 | 要找到什麼 |
|---|---|
| 規則 | 同樣的條件與結果，不能只剩模糊描述 |
| 例外與邊界 | 來源明列的例外，不能只保留通則 |
| 數值與預設值 | 逾時、預設狀態碼等必須在 |
| 測試案例 | 每個案例的前置、觸發、預期的實質內容都在 |
| 圖 | 圖表達的資訊要在，不一定是同一張圖 |
| 決策記錄 | [adr-rules.md](adr-rules.md) 第 1 節的 5 個問題都能回答 |

## 2. 反向對照：新文件 → 來源

完成正向對照後，從新文件反向檢查。每個檔案的實質內容都要能指到來源，並依下表分級：

| 分級 | 處理 |
|---|---|
| 有來源 | 通過 |
| 由來源直接推導 | 通過，逐句核查時標明 |
| 組合推導（把多個事實串成新結論） | 必須改寫為來源的原句意思，或登記授權 |
| 僅程式碼可佐證 | 不得進規範性文件；若要保留，改放說明性文件並註明依據 |
| 新寫的範例程式碼 | 需登記授權，可編譯並與文件逐字同步 |
| 新增規則、行為、數值 | 移除、補來源或登記授權；未處理即不合格（硬規則） |
| 其餘無來源 | 裁量。規則、行為、數值不變的改寫（重新理解後的說法），依第 3 節判更好 / 相當 / 更差。屬下列「通常接受」者免處理 |

通常接受與通常拒絕的例子：

| 通常接受 | 通常拒絕 |
|---|---|
| 銜接句、導覽、索引 | 把兩個獨立事實串成「設計目的」或「因果」的句子 |
| 為了讓類型成立的最少量改寫（如規則改寫成「目標加步驟」） | 補上來源沒有的接線程式碼或設定 |
| 只引用既有事實的整合型文章（實作者回報中說明） | 索引中整理出來源沒有的規則表 |
| 檔頭標示類型與適用範圍 | 以「看起來合理」為由新增規則 |

**逐句來源核查**針對新寫的整合文與導覽：每句標為「有來源 / 可由來源直接推導 / 無來源」，符合上表「通常拒絕」的句子必須改寫、補來源或移除。

## 3. 逐區塊比較：是否變得更好懂

只確認「沒有漏、類型正確」不夠，重構的目的是更容易理解。對來源的每個主要區塊，讀來源再讀對應的新檔案，與第 1 節的對照結果合併成一張表：

| 來源章節 | 保真結果 | 可讀性判定 | 對應位置或說明 |
|---|---|---|---|
| 章節 A | 通過 | 更好 | 新文件位置 |
| 章節 B 引言 | 通過（過程紀錄） | 相當 | 省略清單第 3 項 |
| 章節 C 末段 | **不合格** | 更差 | 找不到某個例外情境的說明 |

可讀性判定：

| 判定 | 意思 |
|---|---|
| 更好 | 重構後更容易找到、更容易理解 |
| 相當 | 差別不大 |
| 更差 | 更難懂、更難找，或需要來回跳轉才能拼出完整意思 |

判斷面向（整體裁量，不逐項打勾）：可找到性（從首頁或檔名一步到位）、理解順序（前置知識在使用處之前或有連結）、認知負擔與粒度（見 `SKILL.md` 粒度雙向裁量）、用詞編排一致，以及原文的好懂之處（一頁式總覽、圖、情境範例）是否被拆散而失去效果。

「更差」必須說明具體原因並建議修法（精確到檔案與位置）。有未解決的「更差」即不合格（硬規則）。

## 4. Migration 專屬的機械檢查

通用項目見 `SKILL.md` 的「機械檢查」，這裡只列 Migration 才有的：

| 項目 | 怎麼查 | 輸出 |
|---|---|---|
| ID 與定義集合 | 來源與新文件中的 ID、編號、術語集合雙向差集；新文件內每個 ID 只定義一次；總數重構前後相同（扣除省略清單項目） | 兩份差集、重複清單；差異只能是已列入省略清單的項目 |
| 搬運型內容 | 大量搬運的內容（如測試案例）用腳本逐一比對 | 一致數、差異數、差異原因；差異應只剩連結改寫等預期項目 |
| 來源未變 | 若約定保留來源檔案，用版本控制的差異摘要或雜湊確認未被改動；新文件是否可連向來源，依雙方約定 | 通過或差異 |
| 索引層重疊 | 首頁路徑表、文件地圖、各目錄 README 是否重複列同樣的導覽 | 重疊清單，有就合併 |
