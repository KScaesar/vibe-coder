# 機械檢查與可執行內容驗證

這份文件定義 `SKILL.md` 步驟 4 與步驟 7 的做法。目的是讓「一致」「沒有殘留」這類結論有工具輸出可查，而不是靠目測。

## 原則

- **輸出差集，不只輸出通過或不通過**：例如 ID 雙向比對要列出「來源有、新文件沒有」與「新文件有、來源沒有」兩份清單，方便對照省略清單。
- **規則共用，實作各自一份**：實作者與審查者約定同一組「規則」（如標題錨點的轉換方式、ID 的格式定義、哪些檔案算案例定義），避免因規則不同得出相反結論；但腳本各自實作，不共用程式碼，因為共用的程式若有錯，審查者看不出來。至少 ID 差集與覆蓋矩陣雙向重算，必須由審查者獨立實作。兩邊結論不一致時，先比對規則，再比對實作。
- **腳本放在暫存區，不進專案**；遵守專案既有的執行環境規則。
- **審查者重算的要求**見 [review-protocol.md](review-protocol.md) 第 1 節。

## 檢查項目

| 項目 | 怎麼查 | 輸出 |
|---|---|---|
| 連結與錨點 | 逐檔解析連結，確認目標檔案與標題存在。非英文標題的錨點轉換規則要先用一個已知頁面校準，兩邊一致 | 死連結、壞錨點清單 |
| 自我連結 | 檔案連到自己 | 清單 |
| 孤兒檔 | 統計每個新文件的入站連結數；入站只來自目錄頁或索引的，確認從 intent-doc 可達 | 入站為 0 或不可達的清單 |
| 殘留 | 搜尋舊章節編號、舊檔名、舊路徑 | 匹配行與位置 |
| ID 集合 | 來源與新文件的 ID 雙向差集；新文件內重複定義；總數（扣除省略清單） | 兩份差集、重複清單 |
| 覆蓋矩陣 | 矩陣與各案例標註的對應需求雙向重算，逐格比對 | 格數與不同格數，列出差異格 |
| 搬運型內容 | 逐項比對來源與新文件的內容 | 一致數、差異數、差異原因 |
| 來源未變 | 若約定保留來源，用版本控制的差異摘要或雜湊確認 | 通過或差異 |
| 外部引用 | 程式註解、README 指向的路徑是否存在；程式端改動以差異確認只涉及預期範圍 | 缺失路徑、非預期改動 |
| 解析端相容 | 見 [migration-acceptance.md](migration-acceptance.md) 第 6 節；跑解析端測試，確認讀到的是新位置而不是被跳過 | 測試結果與讀到的檔案數 |
| 重複事實 | 無法完全機械化：可用關鍵句搜尋找候選，再由審查者判斷是否違反 SSOT | 候選清單，標明為判斷 |

## 可執行內容驗證

文件內的程式碼、指令與設定範例，在不改動被驗證專案的隔離環境中實際執行：

- 使用臨時目錄或獨立模組，以本地路徑參照被驗證專案，不寫入專案目錄。
- 逐字取用文件中的區塊，不手動修補後才執行；需要的接線若文件沒有寫，本身就是缺漏。
- 範例若被固化進專案，需有測試確認文件區塊與範例檔逐字同步，並留意排版差異（縮排、空白）造成的假性失敗。
- 此步與讀者走查分工：走查只讀不跑，可用性結論以這裡的執行結果為準。
