# 情境 → 指標公式

把一句模糊的話（「AI 費用好像太高」「工程師好像變慢了」）變成一條可驗證的恆等式，並標註每一項該往哪走、誰可控、動了會不會傷到別的地方。

產出不是指標清單，是**恆等式 + 方向與可控性標註 + 量測落地表**。

依序執行 Phase 0 到 4，不要跳號。Phase 0 是硬性關卡。

---

## Phase 0：強制反問

先問再拆。即使使用者已經給了大量細節也要問——模糊情境最常見的失敗不是拆錯，是自己腦補了標的量然後一路推下去，產出一份看起來很像那回事、但答非所問的公式。唯一可跳過的情況是使用者明說「不要問，直接給」。

有互動式選項工具就用它（一次最多 3 題、每題 2-4 個選項）；沒有就用編號問題。固定問這三件事：

| 要問什麼 | 為什麼非問不可 |
|---|---|
| **標的量與方向** | 決定公式左邊是什麼。同一情境可能有兩個方向相反的標的量並存（用量要長、支出要持平），沒問清楚會拆錯邊 |
| **資料粒度可得性** | 決定鏈能拆多深。拆到量不到的粒度等於沒拆 |
| **護欄** | 決定哪些項目是綠色的。不問這題，產出會變成「每一項都該下降」，那是錯的 |

資料粒度那題要留一個**比預期更低的底**（「以上都沒有」或開放填寫）。使用者的實際狀況常常比框架設想的最低檔還低；選項不夠低他只能勉強選一個，整條鏈就建在錯的前提上。

邊界與口徑（時間窗、什麼算一次、退款算不算）不要用問的，寫成假設讓使用者否決。問太多題他會放棄；寫成假設他不回也能繼續跑。

問完先輸出確認，再往下：

```
我理解你要解的是：<標的量>（單位：<單位>），方向是 <增加／降低／持平>。
我做了這些假設，錯的話直接說：
1. ...
```

標的量寫不出單位就退回 Phase 0 重問。單位是唯一的真理，寫不出單位的不是指標，是感覺。

## Phase 1：選擇分解算子

看標的量的型態選一種，不要每次都拆乘法。

| 標的量長什麼樣 | 算子 | 檢查方式 |
|---|---|---|
| 一群東西的總和（MAU = 新+留存+回流） | **加法分解** | MECE：各支加總等於母體、無重疊 |
| 規模 × 強度 × 單價（成本、營收） | **乘法鏈** | 連鎖抵消 + 正交性 |
| 存量隨時間變化（訂閱數、庫存、佇列） | **存量流量**：期末 = 期初 + 流入 − 流出 | 流入流出各自再分解 |
| 一個比率（轉換率、填充率、毛利率） | **拆分子分母**，不要直接拆比率 | 見下方 |
| 不是量，是**散**（估不準、忽快忽慢） | **離散度分解**：先拆乘法鏈，再取對數 | 各項變異佔比加總接近 1 |

**拆乘法鏈時不要用 MECE 檢查。** MECE（互斥且窮盡）是加法世界的規則；乘法項本來就不互斥也不窮盡，用錯工具會拆出怪東西。乘法鏈的對應規則是另外兩條：

- **連鎖抵消**取代窮盡：相鄰項的分子分母要能約掉，最後單位等於標的量的單位
- **正交性**取代互斥：兩項若總是同漲同跌，就是同一效應被算了兩次，合併或重新定義

MECE 只在加法分解與維度切片時才拿出來用。

**比率先拆分子分母。** 直接對比率做乘法分解會被加權效應咬到——每個分群都改善了、總比率卻變差（Simpson's paradox）。要嘛拆分子分母，要嘛把它當成鏈中的一項而不是鏈本身。

**使用者抱怨「估不準」時選離散度分解，不要去拆平均值。** 標的量是分佈的散度而不是平均，而改善平均跟改善變異是兩件事，只拆平均會給出答非所問的方案。做法是先照乘法鏈拆出各項，再取對數把乘法變加法，變異數就能歸因：

$$\mathrm{Var}(\ln L) = \sum_i \mathrm{Var}(\ln X_i) + 2\sum_{i<j}\mathrm{Cov}(\ln X_i, \ln X_j)$$

哪一項變異佔比最大就是主因；共變異項不小代表有共同的瓶頸資源。排隊型系統在高利用率下，變異的惡化速度快過平均（約 1/(1−ρ)² 對 1/(1−ρ)），所以「平均只差一點但估不準很痛」是標準病徵，不是使用者的錯覺。

情境複雜時可以混用：頂層乘法鏈，其中某一項再往下做加法分解。

## Phase 2：遞迴展開（Why so?）

每層拆 3 到 5 項。少於 3 項通常沒拆完，多於 6 項通常是把不同層級混在一起。

三個停止條件，滿足任一即停：

1. 這一項已經對應到一個**有人負責、可以改**的東西
2. 再拆下去邊際資訊量明顯下降
3. 這一項是**外生的**——只能換供應商或重新談判，內部使不上力

每一層追問一句：**這條鏈在這個領域有沒有隱藏的漏損環節？** 通用漏斗展開常常漏掉領域特有的那一格，而問題往往就藏在那裡（廣告變現鏈裡的「計費完成率」：拼接成功 ≠ 上報成功）。這類環節的共同特徵是發生在系統邊界外、目前沒有單獨量測、而且剛好能解釋「A 有長但 B 沒動」。

## Phase 3：方向與槓桿標註（So what?）

這是整份產出的價值核心。每一項都要標顏色、副作用、優先度。

| 標記 | 類別 | 判準 | 方向 |
|---|---|---|---|
| 🟢 | **護欄項** | 它成長代表產品有價值；壓它等於自傷 | 上升（明講不得犧牲） |
| 🔴 | **主戰場** | 內部工程或流程可控，壓下去沒人反對 | 下降 |
| 🟡 | **權衡項** | 可控，但動它會傷到體驗、留存或品質 | 需決策，不預設方向 |
| ⚪ | **外生項** | 供應商定價、市場條件，只能換或談 | 下降（手段是採購不是工程） |

不要省略黃色。併進紅色會產出「砍就對了」的建議；併進綠色會漏掉真正的空間。

**對每個紅色項問一句「壓它會把哪一項推上去？」** 乘法鏈裡壓 A 而 B 上升 1.2 倍等於白做。典型例子：把每請求 token 砍到極致，agent 因為缺上下文而多跑幾輪。發現這種配對就在輸出裡明講，並要求一起監控。

**排優先度不要看影響力。** 乘法鏈每一項的彈性都是 1——任何一項降 10%，對總量的效果完全一樣，所以「哪一項影響大」這個問題沒有意義。要看的是：

```
優先度 ≈ 可壓縮幅度 × 可控性 ÷ 副作用
```

可壓縮幅度指現況離合理值有多遠，通常是冗餘、重試、無效工作的藏身處。

## Phase 4：驗證

輸出前跑完四項檢查：

1. **恆等式**：拿歷史資料代入，左右誤差要能收斂。差太多代表漏項或口徑不一致
2. **單位**：連鎖抵消後等於標的量的單位
3. **加法分支**：各支加總等於母體、無重疊
4. **正交性**：任兩項若在歷史資料上高度相關，合併或重新定義

沒有資料可驗證時明講「這條公式尚未用實際資料驗證過」，不要假裝驗過了。

**標的量量不到時，找充分條件代理。** 「最痛的那件事剛好沒有資料」是常態不是例外。這時不要放棄，也不要隨手抓一個相關指標充數——找一個**成立就足以推出結論**的量。例如想證明估不準、但系統只有實際值沒有承諾值時，用 P85/P50：這個比值大到某個程度，任何估計方法都不可能準，數學上足以證明估不準，且不需要任何新埋點。只有充分條件能這樣用，「有相關性」不行。尾端分位數需要足夠樣本（每個窗口至少數十筆），否則報上去的是雜訊。

## 輸出格式

ALWAYS 用這個結構，不要改成對話式說明——使用者要的是可以直接貼進文件的東西：

```markdown
## 1. 總公式
$$\text{標的量} = A \times B \times C$$
（一句話說明單位如何抵消）

## 2. 指標方向原則
一到兩句：哪幾項該升、哪幾項該降、為什麼分成這兩群。

## 3. 各指標詳細說明
### 🟢 <類別名>（希望它繼續長）
**<指標名>**
- 定義：<白話一句，像「多少人在用」這種程度>
- 目標方向：**上升**
- 原因說明：<為什麼是這個方向，以及壓它會失去什麼>

### 🔴 <類別名>（力氣花在這裡）
### 🟡 <類別名>（需要決策）
### ⚪ <類別名>（外部決定）

## 4. 副作用與交互作用
- 壓 X 會推高 Y，兩者要一起看

## 5. 量測落地
| 指標 | 公式 | 單位 | 粒度 | 資料來源 | 口徑邊界 |
（口徑邊界最常被省略也最常出事，一定要填）
另列一節「需要補的埋點」，按資訊增益排序。

## 6. 我做的假設（請否決）
```

指標分四種角色交付，不要混成一份清單：**標的量**（1 個）、**驅動指標**（紅色，附 owner 與可壓縮估計）、**護欄指標**（綠色，明講不得犧牲）、**診斷維度**（切片用，這裡的切片必須 MECE）。

## 常見錯誤

- **把 MECE 套在乘法鏈上**：用錯檢查工具會拆出怪東西
- **按影響力排優先度**：乘法鏈彈性都是 1，要按可壓縮幅度排
- **全部標成「應下降」**：一定有護欄項，沒有代表 Phase 0 的護欄那題沒問或沒聽懂
- **抱怨「估不準」卻去拆平均值**：算子選錯，該用離散度分解
- **直接分解比率**：先拆分子分母
- **拆到資料拿不到的粒度**：好看但不能用。拆不到就明講要補什麼埋點，按資訊增益排序
- **省略口徑邊界**：兩個團隊用同一個指標名字算出不同數字，都是這裡出的問題
- **產出 30 個指標的清單**：核心公式 6 項以內，其餘是診斷維度，分開放
